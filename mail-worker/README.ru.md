# mail-worker

🇬🇧 [In English](README.md)

Это путь для продвинутых: нужен свой домен в Cloudflare и `wrangler`. Проще — отдельный ящик: [docs/connect/mail.md](../docs/connect/mail.md).

Cloudflare Email Worker для мониторинга **писем безопасности** в боте. Ваш ящик пересылает уведомления безопасности ваших аккаунтов (новый вход, смена пароля или почты, смена 2FA, коды входа) на адрес на вашем домене; воркер хранит отправителя, тему и первые 4 000 символов текста в KV, пока бот их не заберёт (раз в 5 минут) и не удалит. Разбирает письма сам бот.

Чего воркер не получает никогда: вашего пароля, вашего ящика, писем, которые вы не пересылали. Письма, которые бот не забрал, удаляются через 14 дней.

## Что он создаёт в Cloudflare

| Ресурс | Имя | Как удалить |
|---|---|---|
| Воркер | `socialbot-mail` | `npx wrangler delete` |
| KV namespace | `EVENTS` | `npx wrangler kv namespace delete --binding EVENTS` |
| Секрет воркера | `TOKEN` | удаляется вместе с воркером |
| Правило Email Routing | ваш адрес → `socialbot-mail` | Email → Email Routing → Routing rules |
| DNS (от Email Routing) | MX и SPF TXT на домене или поддомене, который вы направляете на воркер | Email Routing → Settings → Disable |

И в вашем ящике: адрес пересылки и фильтр. При удалении уберите и их.

## Настройка

1. **Выберите домен.** Он должен быть в Cloudflare. Email Routing ставит на него MX-записи Cloudflare, поэтому **если домен уже принимает почту в другом месте (Proton, Google Workspace…), берите поддомен**, например `alerts.example.com`: Email Routing → Settings → Add subdomain. Почта основного домена останется нетронутой.
2. **Разверните воркер:**
   ```bash
   cd mail-worker
   npm ci
   npx wrangler kv namespace create EVENTS   # paste the printed id into wrangler.toml
   openssl rand -hex 32                      # the token
   npx wrangler secret put TOKEN             # paste the token
   npx wrangler deploy
   ```
   **До деплоя задайте `ALLOWED_SENDERS`** в `wrangler.toml` — ящик, который будет пересылать (например, `me@gmail.com`): письма от всех остальных отклоняются, а пустой список отклоняет всё. Без этого любой, кто узнал адрес, мог бы присылать в ваш чат поддельные «тревоги безопасности». Подтверждение пересылки от самого Gmail пропускается. Если пересланные письма не доходят, `npx wrangler tail` покажет отклонённого отправителя из конверта письма — его и добавьте.
3. **Направьте адрес на воркер.** Email → Email Routing → Routing rules → Create address: локальная часть, которую не угадать (`sec-7f3a9c@alerts.example.com`), действие **Send to a Worker** → `socialbot-mail`.
4. **Подключите бота.** `SECURITY_MAIL_URL` — адрес воркера (`https://socialbot-mail.<account>.workers.dev`), `SECURITY_MAIL_TOKEN` — токен. Перезапустите бота; `/modules` покажет «Письма безопасности» включёнными. Или подключите воркер в чате, без перезапуска: 🔌 Подключения → ✉️ Письма безопасности → «☁️ Свой воркер на Cloudflare» — адрес воркера, затем токен; бот проверит их живым запросом к воркеру, прежде чем сохранить.
5. **Настройте пересылку из своего ящика.**
   - **Gmail:** «Настройки» → «Пересылка и POP/IMAP» → «Добавить адрес пересылки» → адрес из шага 3. Gmail пришлёт туда подтверждение (оно проходит `ALLOWED_SENDERS`), а бот перешлёт вам, как подтвердить: код, который вы вводите в тех же настройках Gmail, или — так Gmail пишет с 2026 года, только ссылкой — собственную ссылку подтверждения Gmail. Бот передаёт только ссылку вида `https://mail.google.com/mail/vf-…`: она открывает страницу Google, где названы оба адреса, а других ссылок из письма бот не показывает, так что поддельное подтверждение не заставит его переслать фишинговую ссылку. Если нет ни кода, ни ссылки, бот так и скажет; в настройках пересылки Gmail письмо можно отправить повторно («Resend email»). Затем «Настройки» → «Фильтры» → «Создать фильтр», в поле «От» — отправители уведомлений безопасности, которые вам действительно приходят, например
     `no-reply@accounts.google.com OR security-noreply@linkedin.com OR security@mail.instagram.com OR security@facebookmail.com`
     → «Переслать» на адрес из шага 3. Чтобы проверить точный адрес отправителя, откройте недавнее письмо безопасности.
   - **Аккаунты, на которых держатся ваши продукты и домен** — второй фильтр, чтобы до вас дошли и чужой токен на GitHub, и новый владелец вашего сайта в Search Console. «От»:
     `noreply@github.com OR account-security-noreply@accountprotection.microsoft.com OR noreply@id.yandex.ru`
     → «Переслать» на адрес из шага 3. А из Search Console — только письмо о новом владельце, не ежемесячную статистику: «От» `sc-noreply@google.com`, «Содержит слова» `"new owner" OR "новый владелец" OR WNC-627102`.
   - **Proton** (платные тарифы): Settings → Filters → фильтр на тех же отправителей с действием *Forward to*.

   Что бот распознаёт в письмах этих отправителей — каждая фраза взята из настоящего письма или со страниц самого сервиса, ничего не придумано:

   | Отправитель | Что распознаётся |
   |---|---|
   | GitHub `noreply@github.com` | «Please review this sign in» 🔴, «Please verify your device» (код), «… has been added to your account» — токен, SSH-ключ, OAuth- или GitHub-приложение 🔴, «An email address was added» 🔴, «Your password has changed / was reset» 🔴, смена passkey или двухфакторной защиты 🔴 |
   | Microsoft `account-security-noreply@accountprotection.microsoft.com` | необычная активность входа 🔴, смена пароля 🔴, код безопасности, оповещение безопасности |
   | Яндекс ID `noreply@id.yandex.ru` | смена номера телефона 🔴, создан пароль приложения 🔴, привязан аккаунт 🔴 |
   | Search Console `sc-noreply@google.com` | «New owner for …» / «У сайта … появился новый владелец» (message ID WNC-627102) 🔴 |
   | Яндекс.Вебмастер `devnull@webmaster.yandex.ru` | уведомление «Делегирование прав на управление сайтом» 🔴 — по страницам справки; образца письма пока нет |

   Письма самого Cloudflare намеренно не включены: о новых входах и новых API-токенах там сообщает [TofsDevOps](https://github.com/morgunovtech/Tofs_DevOps_bot), который читает журнал аудита аккаунта; если пересылать их и сюда, каждая тревога пришла бы дважды. Не покрыты, потому что нет ни настоящего письма, ни задокументированной темы: Bing Webmaster (новые пользователи сайта), Railway (паролей у него нет; коды входа по почте присылает сторонний сервис, Magic), Proton (о новых входах — только push-уведомления). Письмо от этих отправителей всё равно дойдёт до вас как «ℹ️ Письмо без признаков тревоги»; перешлите одно вручную — и его тема может стать правилом.
6. **Проверьте:** перешлите вручную любое письмо безопасности. Бот ответит в течение 5 минут; письмо, которое он не узнал, придёт как «ℹ️ Письмо без признаков тревоги» — так вы увидите, что путь работает.

## Обновление развёрнутого воркера

**Слияние в `main` не разворачивает воркер.** Railway передеплоит бота, а воркер в Cloudflare продолжит работать на коде последнего деплоя, пока вы не обновите его сами:

```bash
git pull
sh mail-worker/update.sh            # dry run: builds and checks, uploads nothing
sh mail-worker/update.sh --deploy   # the same, then deploys and verifies
```

Почему скрипт, а не `npx wrangler deploy`: `wrangler.toml` в репозитории — шаблон, id KV в нём — заглушка, а `ALLOWED_SENDERS` пуст; ваши настоящие значения живут в Cloudflare. Из чистого клона простой деплой упадёт на заглушке, а со вставленным id заменит `ALLOWED_SENDERS` пустым списком — и воркер начнёт отклонять каждое письмо. (Простой деплой безопасен только из копии, где в `wrangler.toml` остались оба ваших значения; скрипт работает из любой.)

Что делает `update.sh`, по порядку:

1. Выгружает закоммиченный `mail-worker/` (`HEAD`, без локальных правок) во временную папку и запускает там `npm ci --ignore-scripts`. В вашу копию репозитория ничего не пишется.
2. Читает привязки версии, которая работает сейчас (`wrangler deployments status`, `wrangler versions view … --json`), и останавливается, если `ALLOWED_SENDERS` пуст или нет `EVENTS` или `TOKEN`: ненастроенный воркер обновлять незачем.
3. Пишет временный `wrangler.toml`: id `EVENTS` берётся у самого развёрнутого воркера, блок `[vars]` убран.
4. `wrangler deploy --dry-run --keep-vars`. Без `--deploy` на этом всё.
5. `wrangler deploy --keep-vars`: `--keep-vars` оставляет переменные, которые есть в Cloudflare, а секреты (`TOKEN`) деплой не трогает никогда.
6. Читает привязки новой версии и сравнивает: `ALLOWED_SENDERS` тот же и не пуст, `EVENTS` — то же пространство имён, `TOKEN` привязан. Затем запрашивает `<worker URL>/events` без токена и ждёт 401.

Если шаг 6 не прошёл, скрипт скажет, что отличается, и выведет путь назад: `npx wrangler rollback <previous version id> --name socialbot-mail`. Id KV и отправители никогда не выводятся и не попадают в отслеживаемый файл.

Полезно знать:

- wrangler нет в `package.json`: `npx` запускает самый новый, как в «Настройке». Скрипт написан под wrangler 4.168 (`deploy --dry-run`, `--keep-vars`, `versions view --json`, `deployments status --json`).
- `WORKER_NAME=…`, если вы переименовали воркер; `WORKER_URL=https://…`, если он отдаётся со своего домена, а не с `workers.dev` (иначе проверка на 401 остаётся за вами).
- Чтобы изменить сам `ALLOWED_SENDERS`: панель Cloudflare → Workers & Pages → `socialbot-mail` → Settings → Variables and Secrets. Следующий `update.sh` сохранит то, что вы там задали.

## Лимиты

Каждый опрос бота — одна операция list в KV: 288 в день при опросе раз в 5 минут. Бесплатный план Cloudflare даёт 1 000 операций list в день, так что не направляйте надолго на тот же воркер второго бота (скажем, локальную копию для разработки). Каждое письмо стоит одной записи и одного удаления (на бесплатном плане — по 1 000 в день каждого).

## API (для бота)

Оба эндпоинта требуют `Authorization: Bearer <TOKEN>`; если секрет не задан, отклоняется любой запрос.

- `GET /events` → `{"events": [{"id", "received_at", "from", "subject", "text"}]}`, сначала самые старые, не больше 50.
- `POST /events/ack` с `{"ids": [...]}` → удаляет их.

## Разработка

```bash
npm ci --ignore-scripts
npm test
```

Тесты покрывают воркер и `update.sh` — скрипт запускается с поддельным `wrangler`, так что до Cloudflare ничего не доходит.
